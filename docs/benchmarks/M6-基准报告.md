## 2. 优先级与来源

```text
CLI 参数  >  环境变量  >  配置文件  >  属性初始化器默认值
```

| 来源 | 触发 | 备注 |
|---|---|---|
| CLI | `--count 2`、`--count=2`、`-c 2`、`--no-flag` | 显式空字符串也覆盖其他来源 |
| ENV | 显式 `[Option(Env = "...")]`，否则 `APP_COMMAND_OPTION` | 大写、非字母数字转 `_`；布尔接受 `1/0`、`true/false`、`yes/no`、`on/off` |
| JSON | `--config <PATH>`（命令前后均可）、`RHL_CONFIG`；启用 `[assembly: RunesHelaConfigFile]` 后追加 cwd / `~/.config/<app>/` 的 `appsettings.json` | `JsonDocument`，无反射 |
| 默认值 | 属性初始化器 | 未设置时保持原值 |

配置键默认 `command.path.option-name`（如 `deploy.environment`、`parent.child.leaf.value`），可用 `[Option(Config = "auth.token")]` 覆盖；同一命令重复键报 `RHL016`，非法键报 `RHL040`。

## 3. JSON 配置

```json
{
  "deploy": {
    "environment": "live",
    "count": 3
  },
  "greet": {
    "tags": ["a", "b"],
    "loud": true
  }
}
```

- 嵌套对象展开为点路径；标量数组与 `"a,b"` 逗号串都可用于数组选项。
- 键匹配 `OrdinalIgnoreCase`；未知键忽略（便于前向兼容）。
- 根必须是对象；数组只允许标量；解析失败不输出任何值。
- 不监听文件变化（CLI 单次执行）。

## 4. Schema（T-048 / M6 退出条件）

`app schema`（兼容 `app schema --config`）输出 draft 2020-12 Schema：

```json
{
  "schemaVersion": "1.0",
  "kind": "config",
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "AotCli.config.schema.json",
  "type": "object",
  "additionalProperties": true,
  "properties": {
    "greet": {
      "type": "object",
      "properties": {
        "text": { "type": "string", "default": "Hello" }
      }
    }
  }
}
```

- 类型映射：`bool`→boolean、整数→integer、浮点/`decimal`→number、枚举→string + `enum`、`Guid`/`Uri`→string + format、数组→array + items。
- `[Secret]` 不输出 `default`。
- 集成测试 `SchemaMatchesDescribeConfigurationKeys` 比对 `schema` 叶子键集合与 `describe` 的 `configKey` 集合，并抽取 `count`/`loud`/`mode` 校验类型与默认值。

## 5. 错误与脱敏（T-049 / AC-17）

| 场景 | 退出码 | 错误码 |
|---|---:|---|
| 显式文件不存在 | 3 | `RHL_CONFIG_NOT_FOUND` |
| JSON 非法 / 根不是对象 / 数组含对象 | 3 | `RHL_CONFIG_INVALID` |
| 值无法转换 | 3 | `RHL_CONFIG_INVALID_VALUE` |
| 必填项缺失（CLI/ENV/配置都没有） | 2 | `RHL_USAGE_MISSING_REQUIRED` |

- 错误消息只包含文件路径与键名，**从不包含值**；`[Secret]` 的 CLI/ENV 值继续显示 `***`。
- Unix 下配置文件对组/其他用户可读且包含 `token`/`secret`/`password`/`key` 键时输出警告；`RHL_NO_CONFIG_WARNINGS=1` 关闭。
- 测试覆盖：非法 JSON 中的 `supersecret`、`greet.pin` 的 `not-a-number` 均不出现在 stderr/JSON。

## 6. 性能与 AOT 权衡

- 未启用隐式发现时，`RunesHelaConfiguration.Load(null, ...)` 返回共享空实例：零分配、零文件 IO，不改变既有热路径。
- 启用隐式发现或显式 `--config`/`RHL_CONFIG` 时才读取文件（预期内的配置成本）。
- 性能门禁复跑通过：5 选项绑定净分配仍与无选项基线一致；解析+绑定烟测 ≤ 10 µs；帮助/错误预算不变。
- `JsonDocument` 为 BCL、AOT 安全且无反射；但 `System.Text.Json` 进入产物后体积明显上升（见下表）。

| 指标 | M5 | M6 | 预算 | 结论 |
|---|---:|---:|---:|---|
| 启动增量 p50 | 0.20 ms | **0.28 ms** | ≤ 1 ms | ✅ |
| 体积增量 | 291.6 KB | **560.7 KB（574,136 B）** | 目标 ≤ 100 KB；失败阈值 > 150 KB | ❌ 超阈值 |

- 体积相对 M5 增加 **269.1 KB**，主要来自 `System.Text.Json`/`JsonDocument`（配置解析）。
- M8 收敛候选：配置解析改为生成期专用最小 JSON 读取器；或将配置支持拆为可选包/可选生成开关，让不使用配置的应用裁掉 `System.Text.Json`。

## 8. 与设计的差异

1. **隐式文件发现 opt-in**：设计 §9.2 默认查找 cwd/用户目录；实现改为 `[assembly: RunesHelaConfigFile]` 启用。原因：默认文件探测会让每次绑定产生 IO 与分配，直接违反 AC-04（0 B、≤ 1 µs）。显式 `--config`/`RHL_CONFIG` 始终可用。
2. **`--help --verbose` 不展开配置键**：配置键通过 `--help --json`、`describe` 与 `docs` 的 `configKey`/`Config` 列暴露，避免为每个命令生成第二份帮助常量、扩大 AOT 体积。
3. **配置文件路径不写入帮助**：由 `RunesHelaConfiguration.Path` 提供；帮助保持静态常量。
