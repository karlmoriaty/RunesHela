## 2. 内置命令

| 命令 | 输出 | 说明 |
|---|---|---|
| `app completion bash` | bash 脚本 | `complete -F` 注册，按路径 `case` 选择候选 |
| `app completion zsh` | zsh 脚本 | `#compdef` + `_describe` |
| `app completion fish` | fish 脚本 | `complete -c`，含描述与短名 |
| `app completion pwsh` | PowerShell 脚本 | `Register-ArgumentCompleter -Native` |
| `app __complete ...` | 每行一个候选 | 隐藏；供脚本/Agent 消费 |

`describe`/`completion`/`docs`/`man`/`__complete` 均注册为保留命令名，用户命令重名会得到 RHL025。

## 3. 静态补全实现

- 由 `CommandModel` 生成一份“路径 → 候选”表：候选 = 可见子命令 + 可见选项（长名/别名/短名）+ `--help`（根另有 `--version`）+ 破坏性命令的 `--yes`/`--no-input`。
- bash/zsh 按 `COMP_CWORD`/`CURRENT` 计算“当前前缀之前的路径”，`case` 命中后交给 shell 原生匹配；支持任意嵌套深度。
- fish 使用 `__fish_use_subcommand` / `__fish_seen_subcommand_from`；PowerShell 使用 `CommandElements` 计算路径。
- 转义：fish 单引号内转义 `\` 与 `'`；PowerShell 单引号翻倍；命令/选项名受生成期命名校验约束。

## 4. 动态补全

```text
app __complete ""            # 根命令与全局选项
app __complete gre           # 以 gre 开头的根候选
app __complete parent ""     # parent 的子命令与选项
app __complete greet --c     # 以 --c 开头的选项
```

- 实现为生成代码中的 `switch (path)`，使用生成期候选数组，无反射。
- 前缀匹配 `OrdinalIgnoreCase`；无候选时退出码 0。
- 候选数组与静态脚本共用 `CompletionData`，避免两套逻辑漂移。

---

## 5. Man / Markdown

- Markdown：`# App` → 每命令 `## <path>`，参数/选项表格，默认值脱敏（`[Secret]` → `***`），嵌套命令递归。
- roff：`.TH` 头部、`.SH NAME/SYNOPSIS/COMMANDS`、每命令 `.TP` 与选项段；`man -l <file>` 可渲染。
- 两者与 help 使用同一 `CommandModel`，字段口径一致（类型、必填、默认值、ENV、描述）。
