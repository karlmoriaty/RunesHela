## 3. 解析基准（5 选项）

输入：

```text
--name runes --count 42 --verbose --tag alpha --output out.txt
```

| 方法 | Mean | Error | StdDev | Ratio | Allocated |
|---|---:|---:|---:|---:|---:|
| HandWritten（手写基线） | 24.42 ns | 1.345 ns | 0.074 ns | 1.00 | 0 B |
| Reader（`CommandLineReader`） | 60.65 ns | 3.791 ns | 0.208 ns | 2.48 | 0 B |

**解读**：
- 原型读取器 **60.65 ns / 0 B**，远低于 1 µs 预算（约 16 倍余量）。
- 相对手写基线慢 **2.48 倍**，主要来自通用 token 化与状态记录；M3 在生成代码中内联为常量比较后目标收敛到 1.2~1.5 倍。
- 分配为 **0 B**，符合“热路径零分配”方向。

## 5. AOT 结果（CI，linux-x64）

### 5.1 本机 Windows AOT：环境阻塞（不影响 CI）

```powershell
dotnet publish samples/AotCli/AotCli.csproj -c Release -r win-x64 -o artifacts/aot/win-x64
```

错误：

```text
Platform linker not found. Ensure you have all the required prerequisites documented at
https://aka.ms/nativeaot-prerequisites, in particular the Desktop Development for C++ workload
in Visual Studio. For ARM64 development also install C++ ARM64 build tools.
```

原因：本机未安装 Visual Studio 的 **Desktop development with C++**（MSVC v143 + Windows SDK），`vswhere`/`cl.exe` 均不存在。

处理：
- `.github/workflows/ci.yml` 的 `aot` job 在 Ubuntu 安装 `clang`/`zlib1g-dev`，完成 AOT 发布、冒烟与测量。
- 本机如需复现：安装 VS Build Tools 的 C++ 工作负载，或使用 Linux 容器。

### 5.2 AOT 启动与体积

| 指标 | EmptyAot（基线） | AotCli（RunesHela） | 增量 |
|---|---:|---:|---:|
| 二进制大小 | 995,696 B（972.4 KB） | 1,095,576 B（1,045.4 KB） | **99,880 B（97.5 KB）** |
| 启动 p50（30 次） | 1.80 ms | 1.80 ms | **0.00 ms** |
| 启动 p95 | 2.29 ms | 2.12 ms | -0.16 ms（噪声内） |

**解读**：
- 体积增量 **97.5 KB ≤ 100 KB**，满足 NFR-05。
- 启动增量在测量噪声内（p50 0.00 ms），远低于 1 ms，满足 NFR-04。
- AOT 绝对体积 **1.05 MB**，适合单文件分发。

### 5.3 单文件回退（非 AOT，仅记录）

| 指标 | 值 |
|---|---:|
| 单文件大小 | 73.56 MB |
| 冷启动 p50（30 次） | 75.9 ms |
| 冷启动 p95 | 140.0 ms |

对照：框架依赖（JIT）p50 = 71.7 ms，p95 = 378.5 ms。单文件含完整运行时，不能用于判断 AOT 预算。

## 8. M0 结论与下一步

### 结论

1. **编译期闭环成立**：`[Command]` → 生成入口/路由/帮助/模块初始化器 → `RunesHelaApp.Run` 可直接运行。
2. **零反射/零分配方向成立**：帮助、错误、路由、解析均为 0 B。
3. **AOT 路径成立**：Linux AOT 启动增量 0.00 ms、体积增量 97.5 KB，均达标。
4. **需要优化**：通用读取器比手写慢 2.48×；M3 生成代码内联后收敛。
5. **待补**：生成器 no-op 基准（M1）、System.CommandLine 对照（T-006）。

### 下一步（M1）

1. 模型 IR、诊断、类型系统、增量管道。
2. 帮助（人类/JSON）快照与产物一致性。
3. 生成器 no-op 基准（NFR-06）。
4. 保持 CI AOT/性能门禁为必过项。
