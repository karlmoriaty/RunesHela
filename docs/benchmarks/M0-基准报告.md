## 3. 解析基准（5 选项）

输入：

```text
--name runes --count 42 --verbose --tag alpha --output out.txt
```

| 方法 | Mean | Error | StdDev | Ratio | Allocated |
|---|---:|---:|---:|---:|---:|
| HandWritten（手写基线） | 24.42 ns | 1.345 ns | 0.074 ns | 1.00 | 0 B |
| Reader（`CommandLineReader`） | 60.65 ns | 3.791 ns | 0.208 ns | 2.48 | 0 B |

**解读**：
- 原型读取器为 **60.65 ns / 0 B**，远低于 1 µs 预算（约 16 倍余量）。
- 相对手写基线慢 **2.48 倍**，主要来自通用 token 化与状态记录；M3 会在生成代码中内联为常量比较，目标回到 1.2~1.5 倍以内。
- 分配为 **0 B**，符合“热路径零分配”方向。

## 4. 框架路径基准（10 命令）

| 方法 | Mean | Error | StdDev | Allocated |
|---|---:|---:|---:|---:|
| Help（`--help`） | 5.98 ns | 0.9252 ns | 0.0507 ns | 0 B |
| Error（未知命令） | 7.77 ns | 0.6337 ns | 0.0347 ns | 0 B |

**解读**：

## 5. AOT 与发布

### 5.1 本地 Native AOT：阻塞

命令：

```powershell
dotnet publish samples/AotCli/AotCli.csproj -c Release -r win-x64 -o artifacts/aot/win-x64
```

错误：

```text
Platform linker not found. Ensure you have all the required prerequisites documented at
https://aka.ms/nativeaot-prerequisites, in particular the Desktop Development for C++ workload
in Visual Studio. For ARM64 development also install C++ ARM64 build tools.
```

原因：本机未安装 Visual Studio 的 **Desktop development with C++**（MSVC v143 + Windows SDK），`vswhere`/`cl.exe` 均不存在。

**处理**：
- 已新增 `.github/workflows/ci.yml` 的 `aot` job，在 `ubuntu-latest` 安装 `clang`、`zlib1g-dev` 后发布 `linux-x64` AOT 并冒烟测试。
- 本机若要跑 AOT，需安装 VS Build Tools（C++ 工作负载）或改用 Linux 容器/CI。

### 5.2 单文件回退测量（非 AOT，仅参考）

命令：

```powershell
dotnet publish samples/AotCli/AotCli.csproj -c Release -r win-x64 `
  -p:PublishSingleFile=true -p:SelfContained=true -p:PublishAot=false `
  -o artifacts/singlefile/win-x64
```

| 指标 | 值 |
|---|---:|
| 单文件大小 | 73.56 MB |
| 冷启动 p50（30 次） | 75.9 ms |
| 冷启动 p95 | 140.0 ms |

对照：框架依赖（JIT）p50 = 71.7 ms，p95 = 378.5 ms。

> 单文件包含完整运行时，**不能**用于判断 AOT 预算；仅证明发布链路可用。

## 8. M0 结论与下一步

### 结论

1. **编译期闭环成立**：`[Command]` → 生成入口/路由/帮助/模块初始化器 → `RunesHelaApp.Run` 可直接运行。
2. **零反射/零分配方向成立**：帮助、错误、路由、解析均为 0 B；解析 60.65 ns，远低于预算。
3. **AOT 代码路径未被证伪**：样例与发布配置就绪；阻塞原因是本机缺 C++ 链接器，不是代码错误。CI 将给出 Linux AOT 结果。
4. **需要优化**：通用读取器比手写慢 2.48×；M3 生成代码内联后可收敛。

### 下一步（M1）

1. 跑通 CI 的 AOT job，记录 Linux AOT 体积/启动（补齐 NFR-04/05）。
2. 建立生成器 no-op 基准（NFR-06）。
3. 进入 M1：模型 IR、诊断、类型系统、增量管道、帮助/JSON 快照。
4. 本机如要继续 AOT：安装 VS Build Tools 的 C++ 工作负载，或使用 Linux 容器。
