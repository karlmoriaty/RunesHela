# M2 基准报告（绑定与 MVP）

> 项目：**RunesHela**
> 阶段：M2（T-015 ~ T-026）
> 日期：2026-11-27
> 结论：**M2 性能通过，AOT 体积超目标。** 帮助仍为 0 B；错误路径因结构化信封产生 304 B（低于 512 B）；启动增量 0.12 ms；AOT 体积增量 125.8 KB，超过 100 KB 目标但未触发 150 KB 失败阈值，交由 M3 优化。

## 2. 框架路径（10 命令）

```powershell
dotnet run --project benchmarks/RunesHela.Benchmarks -c Release -- --filter "*FrameworkBenchmarks*" --job short
```

| 方法 | M0 | M2 | Allocated（M2） | 预算 | 结论 |
|---|---:|---:|---:|---:|---|
| Help（`--help`） | 5.98 ns | 11.66 ns | 0 B | ≤ 5 µs / ≤ 64 B | ✅ |
| Error（未知命令） | 7.77 ns | 76.94 ns | 304 B | ≤ 5 µs / ≤ 512 B | ✅ |
| Route（`cmd5`） | 5.67 ns | 14.48 ns | 24 B | ≤ 1 µs / 0 B（不含用户对象） | ✅ |

**解读**：

- 帮助仍写入 `const string`，分配 **0 B**；耗时增加来自根帮助包含退出码与命令列表。
- 错误路径由“两行文本”升级为 `RunesHelaError`（code/hint/nextSteps/docsUrl/exitCode）：字符串拼接 + 数组 + 对象，实测 **304 B / 77 ns**，在 512 B 预算内。`docsUrl` 已改为编译期常量，避免每次拼接（优化前 584 B）。
- 路由的 24 B 是 `Cmd5` 命令实例，按预算口径不计入框架分配（M3 会单独报告“框架净分配”）。
- 解析基准未变化（未改动 `CommandLineReader` 热路径；仅新增 `PrefixLength` 字段读取）。

## 4. AOT（CI，linux-x64）

| 指标 | EmptyAot（基线） | AotCli（含绑定/帮助/错误） | 增量 | 预算 | 结论 |
|---|---:|---:|---:|---:|---|
| 二进制大小 | 995,696 B | 1,124,552 B | **128,856 B（125.8 KB）** | 目标 ≤ 100 KB；失败阈值 > 150 KB | ⚠️ 超目标、未触发失败阈值 |
| 启动 p50 | 1.79 ms | 1.91 ms | **0.12 ms** | ≤ 1 ms | ✅ |
| 启动 p95 | 2.57 ms | 2.51 ms | -0.06 ms（噪声内） | ≤ 1.5 ms | ✅ |

说明：

- M0 的体积增量为 99,880 B（97.5 KB）；M2 引入选项/参数绑定、人类与 JSON 帮助、结构化错误与脱敏，增量上升 **29 KB**。
- 按设计文档 §12.2，> 150 KB 才判定失败；当前 125.8 KB 处于“超目标但可接受”区间。
- M3 的 T-030（AOT 矩阵）与体积优化将处理该回退：优先评估剥离 JSON 错误渲染、合并错误字符串、按需包含帮助 JSON 常量。
- AC-13 要求“构建成功、0 个 AOT/Trim 警告、产物可运行”——CI 已通过（`Smoke test AOT binaries` 执行 `AotCli --help` 与 `AotCli greet Ada -t Hi`）。
