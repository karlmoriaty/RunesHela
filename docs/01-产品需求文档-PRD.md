## 1. 概述

### 1.1 一句话摘要

**RunesHela 是一个面向 .NET 的编译期 CLI 框架：开发者只声明命令（类或方法），编译器生成解析器、绑定器、帮助、补全、文档、Schema 与 MCP 工具；运行时零反射、零第三方依赖、热路径零分配，并默认对人、脚本与 AI Agent 三类消费者友好。**

### 1.2 目的（为什么做）

- **消除样板**：命令定义、解析、绑定、帮助、校验、补全、文档各自维护，是 CLI 开发最大的重复劳动与漂移来源。
- **消除运行时不确定性**：反射、动态代码生成、运行时格式化让启动慢、AOT 难、行为不可预测。
- **补齐 Agent 契约**：Agent 已成为 CLI 的重要调用者，但现有框架不提供非交互、结构化、可自愈的输出契约。
- **建立可验证的性能信任**：把性能从“口号”变成 CI 预算与公开基准。

### 1.3 目标用户

| 优先级 | 用户 | 关键场景 |
|---|---|---|
| 主要 | .NET 平台/基础设施工程师 | 内部工具、部署 CLI、数据管道（10~100 命令） |
| 主要 | OSS 工具作者 | 单文件分发、跨平台、启动敏感 |
| 次要 | 企业 .NET 团队 | 合规、可测试、可维护、供应链安全 |
| 次要 | AI/Agent 开发者 | 把 CLI 暴露给 Agent/MCP |
| 观察 | 学习者/爱好者 | 5 分钟上手、示例可跑 |

### 1.4 设计理念

1. **编译期优先**：能在编译期确定的，绝不放到运行时。
2. **约定优于配置**：命名、类型、文档注释即可推导出 CLI 行为。
3. **单一事实源**：所有产物从同一模型生成，禁止手写漂移。
4. **契约优先**：输出格式、错误结构、退出码是 API，不是实现细节。
5. **可验证**：每个承诺都有测试、基准或门禁。
6. **可组合**：不绑架渲染、DI、日志、序列化。

## 2. 目标

### 2.1 产品目标

| ID | 目标 | 成功标准 |
|---|---|---|
| G-01 | **优雅**：定义一个类即可获得完整 CLI | Quickstart ≤ 20 行有效代码；无需 `partial`/接口/基类 |

| NG-10 | 兼容所有 POSIX/GNU 语法细节 | 明确取舍，优先单遍解析与可预测性 |

## 4. 背景与上下文

### 4.1 市场空位（摘自 00 文档）

- 类优先 + 零反射 + AOT 同时成立的方案缺失。
- 无框架把 help/completion/man/schema/docs/MCP 作为同一模型的产物。
- 无框架提供 Agent 原生契约（非 TTY、结构化错误、`--yes` 守卫、自描述）。
- 性能缺少 CI 门禁与公开可复现证据。

### 4.2 技术栈

| 层 | 选择 | 说明 |
|---|---|---|
| 目标运行时 | .NET 10（LTS） | net10.0 单目标（D-02=C），支持至 2028-11 |
| 语言 | C# 14 | 扩展成员、`field`、集合表达式等 |
| 生成器 | Roslyn Incremental Generator（netstandard2.0） | 增量、可缓存、快照测试 |
| 运行时依赖 | 0 个第三方包 | 仅 BCL |
| 测试 | xUnit + Verify（快照）+ BenchmarkDotNet + SharpFuzz（可选） | 见 02 文档 |
| CI | GitHub Actions（Win/Linux/macOS × .NET 8/9/10） | AOT/Trim/单文件矩阵 |

### 4.3 设计约束（摘要）

- 运行时不使用反射/动态代码生成（用户代码除外）。
- 生成器不得读取 `Compilation` 造成缓存失效；使用 `ForAttributeWithMetadataName` 与等价模型。
- 所有公开行为必须有诊断码或文档。
- 构建必须确定性、可复现。

## 7. 约束

### 7.1 技术约束

- 仅支持 .NET 10+；不支持 .NET Framework / Unity。
- 运行时不使用反射、`Activator`、`Expression.Compile`、`MakeGenericType`。
- 源生成器必须增量、可缓存、不得持有 `Compilation`。
- 生成的代码必须 nullable 正确、可被 `TreatWarningsAsErrors` 接受。
- 所有产物必须可从编译期模型重建，不依赖运行时扫描。

### 7.2 商业约束

- 许可证为 **Apache-2.0**（D-07=B）：允许商业使用与再分发；需保留 LICENSE/NOTICE 与修改声明。
- 不引入需要付费授权的依赖。
- 不承诺 SLA（除非有商业支持协议）。

### 7.3 依赖关系

- 无第三方运行时依赖。
- 可选集成：`Microsoft.Extensions.DependencyInjection`、`Microsoft.Extensions.Logging`、`System.Text.Json`（均由用户选择）。
- 不依赖 Spectre.Console；提供适配层（P2）。

## 8. 假设

| ID | 假设 | 若假设不成立的影响 |
|---|---|---|
| AS-01 | 目标用户使用 .NET 10+ SDK | 需下调 TFM，牺牲零开销能力 |

## 9. 验收标准（Given/When/Then）

> 验证类型：**P** = 可程序化验证（测试/门禁）；**H** = 需人工判断（评审/体验）。

### 9.1 核心体验

**AC-01（G-01，P）**
Given 一个空的 .NET 控制台项目
When 添加包、定义 1 个 `[Command]` 类并在 `Main` 调用 `RunesHela.Run(args)`
Then 项目可编译运行，`--help` 显示命令/选项/描述，且类不需要 `partial`/接口/基类。

**AC-02（G-01，P）**
Given 一个包含 3 层嵌套类的命令树
When 运行 `app parent child leaf --help`
Then 输出正确的路径、选项与示例，且无运行时反射。

**AC-03（G-01，P）**
Given 一个 5 分钟的 Quickstart 文档
When 一名未接触过该框架的开发者按文档操作
Then 在 5 分钟内得到可运行的 CLI（人工计时，≥ 4/5 成功率）。

### 9.2 性能

**AC-04（G-02，P）**
Given 官方基准项目（5 选项、同步 handler）
When 运行 BenchmarkDotNet
Then 解析+绑定+派发 ≤ 1 µs 且分配 = 0 B（允许 ±10% 机器差异，以基线报告为准）。

**AC-05（G-02，P）**
Given Native AOT 发布配置
When 发布空应用与含 10 命令的应用
Then 启动时间差 ≤ 1 ms（p50），二进制体积差 ≤ 100 KB。

**AC-06（G-02，P）**
Given 50 个命令的项目
When 修改一个无关文件并增量构建
Then 生成器 no-op 时间 ≤ 30 ms，且无全量重新生成。

### 9.3 契约与产物

**AC-07（G-03，P）**
Given `stdout` 被重定向到管道
When 运行任意命令
Then 无 ANSI 颜色/spinner，数据仅在 stdout，诊断仅在 stderr。

**AC-08（G-03，P）**
Given 一个 `[Destructive]` 命令
When 在非 TTY 环境且未传 `--yes` 执行
Then 进程在 1 秒内以退出码 2 失败，并输出含 `nextSteps` 的错误；不得等待输入。

**AC-09（G-03，P）**
Given 任意命令
When 执行 `app --help --json`
Then 输出符合固定 Schema 的 JSON，包含命令、选项、参数、默认值、环境变量、退出码。

**AC-10（G-03，P）**
Given 任意命令
When 执行 `app describe`
Then 输出与帮助一致的完整模型 JSON，可被程序消费。

**AC-11（G-04，P）**
Given 同一版本的 CLI
When 分别生成 help、completion、schema、docs
Then 四者的命令/选项集合完全一致（对比测试）。

**AC-12（G-04，P）**
Given 四个 shell（bash/zsh/fish/pwsh）
When 加载生成的补全脚本并触发补全
Then 命令名与选项名可正确补全（冒烟测试）。

### 9.4 工程质量

**AC-13（G-05，P）**
Given 官方示例项目
When 执行 `dotnet publish -c Release -r <RID> /p:PublishAot=true`
Then 构建成功、0 个 AOT/Trim 警告、产物可运行。

**AC-14（G-05，P）**
Given CI 基准基线
When 任一 PR 使解析耗时或分配超出预算 10%
Then CI 失败并输出对比报告。

**AC-15（G-06，P）**
Given 上一大版本的公共 API 基线
When 运行 ApiCompat
Then 无破坏性差异；若有，必须走弃用流程。

**AC-16（G-06，P）**
Given 非法命令定义（重名选项/必填+默认/不支持类型）
When 编译
Then 得到稳定诊断码、可读信息与文档链接，而不是运行时异常。

### 9.5 安全与体验

**AC-17（NFR-22，P）**
Given `[Secret]` 选项
When 展示帮助、输出错误、启用 `--verbose`、执行 `describe`
Then 值均被脱敏为 `***`，且不出现在任何日志。

**AC-18（NFR-26，P）**
Given `NO_COLOR=1` 或 `TERM=dumb`
When 运行任意命令
Then 输出无 ANSI 转义序列。

**AC-19（NFR-28，H/P）**
Given 含中文描述与长选项的帮助
When 在 80 列终端显示
Then 对齐正确、无截断、无乱码（快照 + 人工检查）。

**AC-20（NFR-30，H）**
Given 文档站首页
When 新用户阅读
Then 能在首屏看到“是什么/为什么/30 秒示例/安装命令”。

## 12. 术语表

| 术语 | 含义 |
|---|---|
| 类优先（class-first） | 以类/属性声明命令，框架生成 CLI 行为 |
| 方法优先（method-first） | 以 lambda/方法声明命令，调用点分析生成解析器 |
| 编译期模型 | 生成器从符号构建的不可变命令描述 |
| 产物（artifacts） | help/completion/man/docs/schema/MCP 等输出 |
| 热路径 | 解析 → 绑定 → 派发，不含用户业务逻辑 |
| Agent 契约 | 非 TTY 行为、结构化错误、退出码、自描述等约定 |
| 零反射 | 运行时不做类型元数据查询/动态调用 |
| AOT | Native AOT 发布（`PublishAot=true`） |
